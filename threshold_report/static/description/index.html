Threshold Report

A Financial Security Threshold report that combines accounting data with manual inputs, exported as an Excel workbook for detailed cash-flow analysis.

What This Module Does

The Threshold Report module helps you generate comprehensive financial security assessments by combining posted accounting data with manual adjustments. It creates a detailed cash-flow analysis covering key financial items such as salary, depreciation, changes in receivables and payables, inventory changes, debt retirement, investments, savings, and taxes—all exported directly to Excel for easy analysis and reporting.

Key Features

Flexible Account Mapping

Map each report row to one or more accounts with individual percentage weights, or define manual amounts. Mix account-based and manual rows as needed.

Period-Based Analysis

Generate reports for any time period—full year, quarter, or month—with opening and closing date calculations for accurate financial snapshots.

Use Period Change Checkbox

Toggle between posted balances during the period or opening-vs-closing balance differences. Default is period-posted balance; optional for deeper analysis.

Excel Export

Download complete reports as professional Excel workbooks ready for presentation, analysis, or further processing.

Configuration

Step 1: Set Up Account Mappings

Navigate to: Accounting > Configuration > Accounting > Threshold Report Accounts

Here you map each of the nine report rows to accounts that will feed that row's calculation:

  • Salary – Personnel costs
  • Depreciation – Asset depreciation
  • Change in Accounts Receivable – Customer receivables movement
  • Change in Accounts Payable – Supplier payables movement
  • Change in Inventory – Stock changes
  • Debt Retirement – Loan repayments
  • Capital Investments – Capital expenditures (optional; can fall back to manual input)
  • Investor Return – Distributions to investors (optional)
  • Savings – Cash reserves (optional)
  • Taxes – Tax payments (optional)

Account Mapping Details

For each mapping row, you can:
  • Add account lines with individual percentage weights (totaling 100%)
  • Define a manual amount instead of accounts
  • Leave it blank to use the corresponding manual field in the report wizard (only for Capital Investments, Savings, Taxes, and Investor Return)

The "Use Period Change (Closing − Opening)" Checkbox

New in this version: Each account mapping row now has a Use Period Change (Closing − Opening) checkbox.

When unchecked (default):

  • The report sums the account's posted balance during the printed period only.
  • Example: For the period January 1 – March 31, it totals all transactions posted between those dates.

When checked:

  • The report fetches the account's balance as of the period's opening date and as of its closing date, then reports the difference (closing minus opening).
  • Example: For the period January 1 – March 31, it retrieves the balance as of December 31 (opening) and as of March 31 (closing), then shows the difference.

Default behavior by row:

  • Checked by default: "Change in Accounts Receivable" and "Change in Inventory" – these rows historically used opening/closing differences.
  • Unchecked by default: All other rows – but you can enable them for period-change analysis if needed.
  • Not available: "Change in Accounts Payable" – see below for how it is handled.

On module upgrade: Existing mappings for "Change in Accounts Receivable" and "Change in Inventory" are automatically switched on, preserving their historical behavior.

Change in Accounts Payable – Historical Residual Amounts

Important: The "Change in Accounts Payable" row is always computed as a historical opening-vs-closing difference, similar to the "Use Period Change" feature. It does not use today's live residual amount.

How it works: For each matched bill, the system reconstructs how much was actually owed as of the period's opening date and as of the period's closing date, then reports the difference between those two amounts. This ensures accurate cash-flow reporting even if bills have been paid off or adjusted after the period ends.

Why this matters: If a bill was unpaid on the report's closing date but has since been paid by the time the report is run, using today's residual would incorrectly show zero. Instead, the system captures the actual amount owed during the period.

Bill matching: The system continues to use the same matching logic to identify which bills belong to your company (via purchase order drop-ship/company address matching). Only the amount calculation changed—from today's snapshot to historical opening/closing values.

Step 2: Configure Companies

Navigate to: Accounting > Configuration > Companies

On any company that should appear in the Threshold Report wizard:

  • Set Related Company (if applicable)
  • Set Required Threshold Report to indicate this company uses the threshold report

Usage

To generate a report:
  1. Go to Accounting > Reporting > Threshold Report
  2. Select the company and the reporting period (year, quarter, or month)
  3. Enter any manual values not covered by account mappings (if applicable)
  4. Click Download Excel Report to generate the workbook

Benefits

  • Accurate cash flow: Combines accounting data with manual inputs for complete financial visibility
  • Flexible period analysis: Generate reports for any time window using opening/closing balances
  • Historical accuracy: Captures actual amounts owed during the period, not current snapshots
  • Easy exports: Excel format ready for presentation and further analysis
  • Configurable: Adapt each row to match your chart of accounts and reporting needs
