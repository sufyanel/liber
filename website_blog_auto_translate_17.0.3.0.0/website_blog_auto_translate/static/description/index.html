Website Blog Auto Translate

Your blog reads in the visitor's language, translated the moment it is asked for and refreshed whenever an author edits a post.

What it does

A visitor switches your website to another language and the blog follows: titles, subtitles, bodies and SEO metadata are machine-translated through Google Cloud Translation while the page is being prepared. Nothing is generated in advance and no batch job has to be planned.

The result is written into Odoo's own translation columns, so the first visitor pays for the call and everyone after that is served straight from the database. When an author edits a post, its stored translation no longer matches the source and is produced again on the next visit.

Features

  • Free, with nothing to sign up for. Translation runs through the deep-translator library. If you would rather not depend on a public endpoint, point it at a LibreTranslate instance of your own instead — one setting, still free.
  • Translated on demand. Blog posts, blogs, tags and tag categories are translated the first time somebody opens them in a language that has no translation yet.
  • Kept in sync with the content. Every translated field stores a fingerprint of the text it was made from. Edit the post and the fingerprint stops matching, so the field is translated again — fields you did not touch are left alone.
  • Markup is preserved. The body is translated term by term through the same mechanism Odoo's own translation dialog uses, so links, images, snippets and styling come out untouched.
  • Editable afterwards. Translations live in the standard translation columns, so you can correct any of them from the usual Odoo translation dialog.
  • Hand corrections can be frozen. Untick Auto Translate on a post and the module stops overwriting it.
  • No noise in the audit trail. A visitor who triggers a translation is not recorded as the last contributor, and Last Updated on keeps showing the real last edit.
  • Never breaks a page. If the credentials are wrong or Google is unreachable, the error is logged and the page renders in the source language.
  • Fast where it counts. All the sentences on a page travel together in as few requests as the free endpoint reliably accepts, and identical texts are sent once. A whole blog post is translated in about two seconds.
  • Headlines first. Each page render has a work budget, so no visitor waits on a long listing. Titles are always translated first; bodies fill in over the next few views.

Configuration

  1. Install the Python dependency: pip install deep-translator
  2. That is the whole setup for the default provider — there is no key to obtain and no account to create.
  3. Optionally, under Website › Configuration › Settings › Blog Translation, switch the provider to a self-hosted LibreTranslate instance if you would rather not use a public endpoint.
  4. Add the languages you want to serve under Website › Configuration › Settings › Website Info › Languages.

Good to know. The very first visit to a page in a new language is the slow one — that is when its texts are sent off to be translated. Every later visit is served from the database at normal speed. The free endpoint occasionally refuses a request; when it does, the page simply renders in its original language and is translated on a later visit.
